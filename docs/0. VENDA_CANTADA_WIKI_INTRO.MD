# 1. Sobre o projeto
------------------

O **CAOA Venda Cantada** é uma solução web corporativa voltada ao gerenciamento das intenções de venda, permitindo registrar operações comerciais, consultar informações, acompanhar indicadores de desempenho e gerar relatórios analíticos.

A plataforma oferece uma visão consolidada das operações por bandeira, marca, vendedor e período, contribuindo para o acompanhamento de resultados comerciais.

### Principais funcionalidades

*   **Gestão de intenções de venda:** cadastro, consulta, atualização, pesquisa e gerenciamento dos registros comerciais.
    
*   **Dashboard gerencial:** visualização de indicadores, totais, rankings e desempenho por bandeira.
    
*   **Relatórios analíticos:** acompanhamento dos resultados por marca e vendedor, com filtros e recursos de exportação.
    
*   **Autenticação corporativa:** integração com Microsoft Entra ID para identificação dos usuários.
    
*   **Controle de acesso:** administração de usuários, perfis, permissões e telas disponíveis.
    
*   **Integração de dados:** comunicação com APIs e banco de dados SQL Server para persistência e recuperação das informações.

2. Arquitetura e tecnologias
----------------------------

A aplicação utiliza uma arquitetura baseada na separação de responsabilidades entre interface, autenticação, serviços de negócio e persistência de dados.

O código-fonte está organizado em um monorepositório, permitindo gerenciar os componentes frontend e backend de forma integrada.

| Camada | Tecnologias |
| --- | --- |
| Frontend | Next.js 15, React 19, TypeScript e Tailwind CSS |
| Visualização de dados | VisActor |
| Backend | Node.js, Express e TypeScript |
| Persistência | Prisma ORM e Microsoft SQL Server |
| Autenticação | NextAuth e Microsoft Entra ID |
| Testes | Vitest, Supertest e Playwright |
| Containerização | Docker e Docker Compose |
| Versionamento e CI | Git e Azure DevOps Pipelines |
| Publicação | Docker, Nginx, IIS e PM2 |
**Fluxo principal da aplicação:**
`Usuário → Next.js → API/BFF → Express → Prisma → SQL Server`

A autenticação é realizada por meio do Microsoft Entra ID, enquanto as regras de autorização são verificadas pelo backend, considerando os perfis e permissões cadastrados.

3. Ambientes da aplicação
-------------------------

O projeto contempla ambientes distintos para desenvolvimento, homologação e produção, assegurando a separação das configurações, dos dados e dos processos de validação.

| Ambiente | Finalidade | Banco de dados |
| --- | --- | --- |
| Desenvolvimento | Implementação e testes locais | `salesdb_hml` |
| Homologação | Validação funcional e técnica antes da publicação | `salesdb_hml` |
| Produção | Execução das operações corporativas | `salesdb` |

A evolução da infraestrutura contempla a adoção de serviços Microsoft Azure, com foco em automação, segurança, observabilidade e governança.

A arquitetura definitiva de hospedagem em Azure permanece sujeita à avaliação e aprovação técnica.
